Exact per-file declarations and ownership contracts for the planned Zig implementation. No runtime modules have been added yet.

Session redesign status. The linear frame-log draft supersedes snapshot/delta persistence and registry-revision request views as the target architecture. This page retains the earlier storage or streaming design for reference. It is not a specification of the new frame reducer.

Change set

These declarations define the planned API. They omit bodies and private fields but include every parameter and return type. Each owner file uses const Self = @This(). Common aliases are Allocator = std.mem.Allocator, j = @import("json.zig"), and api = @import("abi"). Type names from other files refer to imports of those files.

Identity.init copies request_id. Its other fields are scalars. Identity owns memory and must not be copied. take validates first, then consumes and nulls both optionals on success. On error, the caller retains ownership of both. Body.root selects buffered JSON. Body.response selects the response field of a terminal SSE event. deinit frees the identity and document.

Accessors and CallIterator return views valid until result deinit. publicValue allocates its values in the supplied allocator. It includes the generation, provider response ID, model, usage, public message output, and function-call output. It excludes reasoning and opaque private items. output retains every original item for model replay. The result needs no separate answer buffer or copied call-string array.

create copies Origin into ModelResult.Identity. acceptMeta borrows strings for the call and stores a mode enum. Duplicate or missing metadata, a wrong MIME type, a non-UTF-8 charset, or non-identity encoding rejects the stream. Protocol errors become Failure values rather than Worker faults. Failure has no borrowed strings or heap allocation.

advance subtracts consumed bytes and frames from the budget and returns one action. Worker and ProgressBatch charge budget.events separately. While an update is pending, advance returns the same view without consuming input. acknowledge frees that Decoded only after offer returns accepted or the caller discards it. Never acknowledge after blocked or yielded. advance decodes frames before reporting their bytes consumed.

Call finish once, after consuming all earlier DATA. It records the transport end. advance performs any final buffered-JSON parse. ready requires HTTP success, validated completed output, and transport done. takeResult transfers the result once. Afterward, do not use origin or result views through the stream.

On stream_fault, Worker prepares and publishes one abort plus any required IO_CANCEL, then calls acknowledgeFault. Until that call, advance repeats stream_fault without consuming input. It then discards DATA within the byte budget and returns failed only after terminal delivery. Worker stages the failed command at that point. After a stop commits, retire discards previews and results, drains input, then returns retired. work.stop chooses cancellation or steering. destroy releases all remaining state, including partial frames.

Allocation failure propagates. If decoding exceeds its memory quota, Worker calls reject(limit_exceeded). A system allocation failure may fault the worker instead. Allocator state backing a ModelResult must outlive that result, even after the stream is destroyed.

Add EventOutbox.zig

Owns every prepared or published event buffer, its queue slot, and its lease. The old Event implementation becomes private here.

pub const Class = enum { progress, control, committed };
pub const Limits = struct {
    slots: u32,
    bytes: usize,
    progress_slots: u32,
    progress_bytes: usize,
    max_event_bytes: usize,
};
pub const Record = struct {
    class: Class,
    kind: u32,
    operation_id: u64,
    sequence: u64,
    request_id: []const u8,
    method: []const u8,
    payload: j.Value,
};
pub const Batch = struct { id: u64, remaining: u32 };
pub const PrepareError = Allocator.Error || error{LimitExceeded};

pub fn init(allocator: Allocator, limits: Limits) Allocator.Error!Self;
pub fn deinit(self: *Self) void;
pub fn prepareBatch(
    self: *Self,
    records: []const Record,
) PrepareError!?Batch;
pub fn publish(self: *Self, batch: *?Batch, count: u32) void;
pub fn discard(self: *Self, batch: *?Batch) void;
pub fn next(self: *Self, output: *api.cpi_agent_event) bool;
pub fn release(self: *Self, lease_id: u64) error{StaleEvent}!void;

prepareBatch borrows records for the call and serializes them into independent immutable buffers. Null means capacity is temporarily unavailable. It takes no record ownership. Oversized events or batches return LimitExceeded. Preparation reserves slots and encoded bytes for the entire batch, including all event classes. It cannot evict delivered events.

publish moves the next count prepared events into preallocated queue slots without allocation or failure. It reduces remaining and nulls the handle at zero. discard releases only unpublished entries and nulls the handle. Published leases remain valid. Batch is a unique reservation handle and must not be copied. next creates exactly one delivered lease when it returns true. Call release only after the driver has joined all readers.

A commit batch starts with the journal IO_REQUEST, followed by committed notices. Worker publishes the request before I/O and the notices after the durability acknowledgment. Reserving them together prevents notices from consuming the space needed to dispatch their own append. Worker checks that slots and bytes outside the progress allowance can hold the largest permitted commit batch and control events. A batch larger than its configured limit returns LimitExceeded rather than retrying null forever. The host must still release held control and committed leases.

Add ProgressBatch.zig

Owns only unpublished preview copies and the closed-generation watermark. It has no provider parser or Worker reference.

pub const Limits = struct {
    max_records: u32,
    max_bytes: usize,
};
pub const Offer = enum { accepted, blocked, yielded, obsolete };
pub const Flush = enum { done, blocked, yielded };
pub const Error = Allocator.Error || error{LimitExceeded};

pub fn init(allocator: Allocator, limits: Limits) Self;
pub fn deinit(self: *Self) void;
pub fn offer(
    self: *Self,
    outbox: *EventOutbox,
    origin: ModelResult.Origin,
    update: *const ResponsesDecoder.Update,
    events_left: *u32,
) Error!Offer;
pub fn flush(
    self: *Self,
    outbox: *EventOutbox,
    events_left: *u32,
) Error!Flush;
pub fn discard(self: *Self, generation: u64) void;

accepted means the update was copied or synchronously published, so ModelStream may acknowledge it. blocked means outbox capacity is unavailable. yielded means the publication budget is exhausted. Neither consumes any part of the supplied update, though an earlier batch may have flushed. obsolete means the generation is closed and the caller may acknowledge and discard the update. events_left decreases only on successful publication. Zero budget returns yielded only when publication is needed.

Merge only adjacent records with the same generation, item, part, and channel and contiguous UTF-8 byte offsets. A single large delta may bypass merging within the configured event limit. Limits must fit a maximum accepted delta. Permanent size errors must not cause endless blocked retries. Publish synchronously after preparation so no prepared progress batch survives a method call. discard drops unpublished data and rejects later offers for that generation. Worker supplies abort and commit notices separately through its reserved batch.

Operation.Kind is enum { read, write, http, effect }. request returns null when output or operation capacity is temporarily unavailable, without dispatching an operation. For http, Worker assigns the operation ID and creates its ModelStream before publication. Exceeding a permanent limit returns LimitExceeded. feed copies accepted data once. WouldBlock copies nothing and consumes no quota. nextEvent and release delegate lease storage to the outbox.

stage keeps its current consume-on-success contract, but success now queues an owned Commit even if output space is unavailable. Notice payloads must already belong to document, or be immutable; stage copies the notice array and request IDs into that arena without cloning those payloads again. On error the caller retains document; current state is untouched. It stamps committed records with Commit.sequence and control/progress records with zero; READY uses the control class. While queued, io.pumpCommit prepares one batch containing the append request and its notices. Only then may it publish the request and mark writing. On ack it swaps state and publishes the reserved suffix. No other state mutation occurs during either phase. This avoids changing every Lua/effect caller to retry after it already finished.

run prioritizes journal acknowledgments, queued commits, and control messages over bounded stream work. Budget exhaustion returns RUNNABLE. Waiting for capacity, input, or an acknowledgment returns WAITING. Do not dispatch a model request while ready_model exists. Replace private emit and replyIndex calls with outbox preparation and per-operation scheduling. Replace cancelExternal with prepared cancellation notices.

Worker's private DecodeQuota exposes an Allocator, a live-byte count, a configured cap, and a quota-hit flag. It remains at Worker's stable address until every decoded document and result document is freed. Reset the flag before each decode attempt and classify OutOfMemory immediately. Keep allocator callbacks private.

Required call order

  1. work.prepareModel stamps generation, then Worker.stage queues its intent checkpoint. Dispatch waits for the durable ack.
  2. model.dispatch starts HTTP. Worker creates ModelStream and reserves its terminal input slot before publishing IO_REQUEST.
  3. io.pump feeds raw prefixes to ModelStream.advance. For update, ProgressBatch.offer either copies/publishes it or reports blocked/yielded. Only accepted or deliberate discard permits acknowledge.
  4. After the provider terminal and transport DONE, takeResult moves into ready_model. model.acceptResult queues the canonical checkpoint and its final-public-output notice.
  5. io.pumpCommit reserves [append request, notices], publishes only the first, then after fsync ack swaps state and publishes the suffix. Discard that generation's unpublished progress before publishing its close notice.
  6. Lua may start after the result ack. Native effects still wait for their separate intent ack. Transport failures and cancellation never turn argument previews into calls.
