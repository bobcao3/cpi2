Small durable writes.

Session commits state before dispatching external work. Journal stores checkpoints and structural JSON deltas in one gzip-framed file.

The WAL holds working state. The history archive holds immutable entries, completed command outcomes, and completed effect bodies.

Two implementation pieces

  • Journal.zig owns append, reconstruction, limits, locks, and checkpoint replacement.
  • journal_delta.zig computes and applies set, remove, and array-splice edits.

Session still owns its independent mutable candidate. Journal prepares its owned snapshot and frame before I/O. Session installs state and publishes notices only after the commit succeeds.

One transaction per frame

A checkpoint stores the complete state. A delta names its preceding logical sequence and records only structural changes. Both use the existing checksummed gzip framing.

Unchanged object members and array prefixes are not written again. A full checkpoint remains available when it is smaller or a delta cannot fit. Full state walks and candidate cloning remain accepted CPU and memory costs.

Replacement preserves identity

Retention limits trigger a candidate checkpoint at the next logical sequence. Journal syncs an exclusive temporary, renames it over the journal, and syncs the parent directory. A stable lock remains held throughout replacement.

Physical counters reset. Logical sequence, command receipts, retained conversation data, and the existing effect namespace do not.

Reconstruction never executes effects

Recovery validates framing, checksums, identity, sequence, edits, depth, and materialized size. Complete corruption fails without rewriting bytes. Only incomplete final members are repaired.

Interrupted running work is not replayed. Recovered queued commands stop as interrupted by default. Embedders can explicitly select queued resumption. Known results remain available.

Session graph and history

Journal stores checkpoints and deltas. Minimal keeps an application session graph and pages immutable entries from the history archive. Startup rejects malformed records and state without changing source bytes. Native conversation adoption transfers exact entries atomically.

Keep the first cause

Native waits and failed reads retain the original error. Outstanding waits settle before execution services join. Minimal can leave a failed notification wait and clears interrupted tool panels without inventing durable outcomes.

Verify behavior, not a diagram

The repository checks cover patch fixtures, small-write regression, malformed-state denial, replacement, torn and malformed records, allocation failures, sync failures, cancellation, deduplication, and crash no-replay after checkpointing.

These checks do not prove power-loss behavior on arbitrary hardware. The implementation does not claim changed-only CPU cost or fixed space for indefinitely retained novel data.
